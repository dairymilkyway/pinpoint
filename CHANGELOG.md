# Changelog

2026-10-04 feature:favicon-and-page-titles - the site gets a real icon set: a map pin matching the landing page's pins, shipped as favicon.ico (16 and 32), favicon.svg and a 180px apple-touch-icon, with the head now declaring all three plus a theme-color. favicon.ico had been Laravel's 0-byte stub, so every browser drew a blank tab. The browser tab stops lying too: the landing page reads "Pinpoint" rather than "Pinpoint - Pinpoint", and two mislabelled screens are named for what they are, the reader's front door becoming "Address owners" and the owner-picker "Choose an owner". The header brand mark was a crosshair glyph, which is what the stylesheet beside it always said it should not be - it is now the same pin path as the favicon, byte for byte, in all eight places the brand appears. The apple-touch-icon is transparent rather than full-bleed: iOS composites it over black and applies its own mask, so the rounded plate sits on transparent corners instead of a black square.

2026-10-04 feature:landing-pin-pop - the sonar pulse on the landing atlas is replaced by map pins: twelve randomly chosen cities each get a pin that pops up out of its own tip with a slight overshoot, holds, fades and returns on a six second cycle. Each pin carries its own delay so they never arrive together, and the pick is fresh on every render. Under prefers-reduced-motion the pins sit visible and still.

2026-10-04 feature:atlas-caption-removal - the landing map loses the caption beneath it and the Exact location / Approximate location key that went with it, along with the six CSS rules that styled them. The svg aria-label still states the same region and city figures, so a screen reader loses nothing.

2026-10-04 feature:landing-copy-and-pulse - the landing page leads with Pinpoint instead of "Philippine addresses", its hero paragraph stops naming the three roles, and feature 02 describes the approval queue rather than permissions. A random handful of the archipelago's city dots now pulse, so the map reads as live; each pulse is given its own delay so they never beat in unison, and the animation is off under prefers-reduced-motion. The atlas aria-label deliberately still describes a map of the Philippines - it is what a screen reader gets in place of the drawing.

2026-10-04 feature:sign-in-single-column - the sign-in page drops the archipelago panel and is now a single centred card, the same shell register and the password screens already use. The panel went because the atlas is portrait - viewBox ratio about 0.485 - so inside the column beside the form it could not be both legible and matched to that column's shape: capped, it was a narrow strip in a very wide panel; uncapped, it overflowed and was clipped. The landing page keeps its own full-size map, so `.atlas`, `.atlas__dot` and `.atlas-caption` all stay. This also retires the `.auth-split` and `.auth-plate` rules, which existed only to seat that panel.

2026-10-04 feature:premium-chrome-and-alignment - the top bar is now pinned to the top of the window and frosted, over a sidebar that sticks and scrolls on its own; the public landing page gets the same surface plus the light/dark switch it had been missing. Two alignment fixes ride along: the sign-in page's map panel lines up with the card again, and the dashboard map now fills its panel instead of leaving a gap under it.

2026-10-04 feature:login-fit-and-toasts - the sign-in page fits one screen: the archipelago panel is height-capped instead of stretched to the card, and the demo account picker is a compact row of three instead of three tall cards. Every flash message now arrives as a toast in the bottom-right corner, so a message no longer pushes the page down.

2026-10-04 feature:pinpoint-rename-and-plain-copy - the product is renamed Pinpoint, with a crosshair mark in all eight places the brand appears, the "address book" wording removed everywhere a reader could see it, and the user-facing copy on every screen rewritten in plain English (the coverage hint now says "are on the map" instead of "have coordinates").

2026-10-04 feature:directory-table-and-requests - the addresses directory drops its Map and Default columns (the default marker now rides inline beside the name), its toolbar buttons are full size and aligned, and each request row shows the requester's reason instead of keeping it behind the Review button.

2026-10-04 feature:user-deactivation - a Superadmin can deactivate an account from the Roles & permissions screen and reactivate it from the same row. Deactivating blocks sign-in only: the account's addresses stay in the book, keep their owner's name, and stay reachable from the directory. The import page fills the page width, and Export to Excel now carries the same box as New address and Import Excel.

2026-10-04 feature:rbac-audit-log - the four Roles & permissions actions now write to the audit log: a role change, an account deactivation, an account reactivation, and a permission-matrix save (one entry per role whose set actually moved). A refused action and a save that changes nothing record nothing, so the log holds acts rather than attempts.

2026-10-04 feature:customer-import-proposals - a Customer's own addresses page now carries New address, Import Excel and Export to Excel; the first two file a request instead of writing, so a single new address or a whole imported spreadsheet waits as one entry in the reader's queue until it is approved or rejected, and a Customer can export the rows they can already see.

2026-10-04 feature:dashboard-focus-and-chrome - the setup, create, edit and request panels now sit centred instead of hard against the left edge, destructive confirm buttons (Deactivate, Delete, Reject) read as buttons before you hover them, the lead dashboard figure carries a twelve-week sparkline of addresses on file, a Customer gets the By region chart over their own rows without losing their request list, and clicking a region bar narrows the map to just that region's pins with a caption and a Show all way back.
2026-10-04 feature:rbac-action-confirmations - Update and Deactivate on the Roles & permissions screen now open a confirmation dialog first, naming the account and - for a role change - the role it is being moved to, so neither is one stray click from done; the row's Reactivate stays unconfirmed because it is the undo.
2026-10-04 feature:notification-detail-and-inbox - a notification now has a page of its own, rendering the snapshot it was written with rather than re-reading what it is about, so it still makes sense after the request is decided or the address deleted; Open lands there and the page carries a guarded button through to the specific request, which gets its own read-only page showing what was asked for and how it was decided.
2026-10-04 feature:deactivated-account-signin-message - signing in to a deactivated account now says the account has been deactivated and to ask an administrator to reactivate it, instead of claiming the credentials do not match. The real reason is only revealed once the password is known to be correct, so the sign-in form still answers nothing about which addresses have accounts.
2026-10-04 chore:apple-touch-icon-transparency - the 180px apple-touch-icon ships with transparent corners instead of a filled black square.

2026-10-05 feature:phone-number-and-account-settings - every account now carries a mobile number: registration requires one and refuses a landline, one rule accepts the several ways people write a number and stores a single canonical form, and the number shows on the address owners list and on each owner's page, with a rendered dash standing in for the accounts that predate the column. A Customer also gets a page of their own - Account, in the sidebar - to change their name, email and number, to change their password by proving the current one, and to deactivate themselves without losing the addresses they own, which stay in the book with their name attached and an administrator can restore. A Superadmin or Admin is refused that page outright, since neither is the customer here.

2026-10-05 feature:modal-centring-and-transparent-favicon - a confirmation dialog whose form sits directly inside the dialog box no longer drifts left of the centre; one stylesheet rule makes such a form fill the dialog, fixing all four affected modals at once and leaving the two that never had the bug untouched. The site icon is now the pin alone on genuinely transparent ground: the opaque plate behind it is gone, the pin's inner circle is a real hole, and the 180px apple-touch-icon and the multi-size favicon.ico were redrawn from the same glyph.

2026-10-05 feature:realistic-seed-data - the seeded directory now carries real-looking people: firstname.lastname@gmail.com addresses and valid Philippine mobile numbers on every account.
2026-10-05 feature:transparent-brand-mark - the pin logo no longer sits on a chip: the dark-or-white background, its border and its radius are gone from the brand mark, so the pin now sits directly on the page in all eight places it appears, in both themes.
2026-10-05 feature:identical-pin-rendering - the tab icon and the header brand mark are now the same drawing rather than two that resemble each other. The favicon was cropped loosely and cut its centre hole with a mask, so it rendered smaller and thinner in the tab than the same pin rendered in the header; both now share one path string, the hole included as a real subpath, on the same tight crop, so the two render alike at any size. The test that was supposed to guarantee this only compared the path data, which is exactly how the two drifted apart - it now checks the hole is real in every copy as well.
2026-10-05 feature:register-form-placeholders - the register form now hints at every field but one. Name and email show the shape of a real answer, and the password says the minimum it actually enforces rather than leaving a too-short password to be discovered on submit; confirm password stays bare because its label already says what it is. Nothing about validation changed - these are hints, and a test now holds them in place.
